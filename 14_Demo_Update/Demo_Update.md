# 14. 플레이 데모

기획 내용을 검증하기 위해 만든 플레이 데모(`demo/index.html`)의 개요와 개발·검증 과정을 정리한 문서이다. 게임 규칙은 각 시스템 문서가 현재 데모 기준이다.

## 1. 설계 원칙

- 방치형이므로 보상을 받으려고 반드시 눌러야 하는 구조를 두지 않는다. (미션 보상은 예외)
- 새 기능은 해금되는 시점에 튜토리얼로 안내한다. 튜토리얼 중의 조작은 실제 자원을 소모하지 않는다.
- 미션이 곧 성장 가이드가 되도록 튜토리얼과 미션 순서를 연결한다.
- 확률과 천장을 공개하고, 실패해도 직전 스테이지에서 계속 성장하게 해 방치형의 불안을 줄인다.

## 2. 구현 범위

- 전투: 4인 자동 전투, 스킬 자동/수동, 배속, 보스 방어 게이지와 그로기, 제한시간
- 성장: 캐릭터 20명, 레벨업, 돌파, 장비 소환·강화·한계 돌파·분해
- 콘텐츠: 3개 챕터 15스테이지, 일일 던전 3종, 목표 미션, 일일 미션, 출석, 방치 보상
- 시스템: 튜토리얼, 설정, 자동 저장과 이어하기

시스템별 상세는 다음 문서를 참고한다.

- [Stage](../11_Stage/Stage.md), [Gameplay](../03_Gameplay/Gameplay.md), [Combat](../04_Combat/Combat.md)
- [Growth](../05_Growth/Growth.md), [Equipment](../05_Growth/Equipment.md), [Character](../09_Character/Character.md)
- [Gacha](../08_Gacha/Gacha.md), [Economy](../06_Economy/Economy.md), [Content](../07_Content/Content.md)

## 3. 개발과 검증 방식

- 기획서와 설계 결정은 기획자가 직접 하고, 구현과 테스트는 AI(Claude)와 반복하는 방식으로 진행했다.
- 튜토리얼, 던전, 미션 흐름은 헤드리스 브라우저로 자동 테스트했다.
- 권장 전투력과 제한시간은 전투 시뮬레이션으로 보정한 뒤 직접 플레이로 확인했다.
- 플레이 중 발견한 문제는 [Bug_Fix_Log.md](Bug_Fix_Log.md)에 정리한다.

## 4. 변경 이력 (초기 기획 대비)

초기 기획 문서는 [archive/initial_planning](../archive/initial_planning)에 보관하고, 본 문서들은 현재 데모 기준으로 정리했다. 주요 변경은 다음과 같다.

| 항목 | 초기 기획 | 현재 데모 |
|---|---|---|
| 챕터 구조 | 일반 10 + 챕터 보스 | 일반 4 + 보스 1, 3챕터 15스테이지 |
| 재도전 | 직접 재도전, AUTO 도전 | 클리어 3초 후 자동 진행 |
| 핵심 재화 | 골드·소환 재화·캐릭터 조각 3종 | 5종(장비 조각, 던전권 추가) |
| 중복 장비 | 판매 | 분해 |
| 장비 강화 | 최대 +10 | +15(한계 돌파) |
| 소환 | 가격·확률 미확정 | 확정, 천장 도입 |
| 편성 | 같은 직업 여러 명 가능 | 직업당 1명 |
| 스탯 | HP·공격력·방어력 | HP·공격력 (피해 감소는 스킬 효과) |
| 직업 대응 시스템 | 추천 직업별 전용 효과 | 방어 게이지 감소량의 직업 차이만 구현, 정식 버전에서 검토 |
| 몬스터 | 오염된 덩굴수 등 | 포포, 사냥개, 골렘, 보스(챕터별 변형) |
| 전투 실패 | 제한시간 초과, 전멸 | 동일 (제한시간 일반 150초, 보스 240초 적용) |

## 5. 남은 과제

- 직업 대응 시스템과 보스 고유 패턴
- 캐릭터별 개성 강화 (현재 일부 스프라이트는 색 변형)
- 캐릭터 등급 간 스탯 밸런스 재조정
- 다수 플레이어 테스트를 통한 경제·보상 수치 조정
- 진행 데이터 내보내기·불러오기 (현재는 기기별 브라우저 저장)
- 챕터 확장
